# 프로필 갱신 가이드

## 대표 프로젝트 바꾸기

프로필 저장소의 `README.md`에서 `PROJECTS:START`와 `PROJECTS:END` 사이를 수정하세요. 자동 블로그 갱신은 이 영역을 건드리지 않습니다.

1. `### 01 · 준비 중`을 실제 프로젝트 제목으로 바꿉니다.
2. `assets` 폴더에 직접 촬영한 스크린샷이나 GIF를 업로드합니다.
3. 이미지 경로와 대체 설명을 바꿉니다.
4. 소개를 1~2문장으로 적고, 본인이 구현한 핵심 기능을 포함합니다.
5. 기술 주석을 실제 기술 목록으로 바꾸고, 링크를 해당 저장소나 데모로 교체합니다.

```markdown
### 01 · 프로젝트 이름

![프로젝트 플레이 화면](assets/my-project.gif)

어떤 게임/도구인지 소개합니다. 직접 구현한 핵심 기능을 설명합니다.

`Unity` · `C#`

[Repository ↗](https://github.com/KanghyuckMoon/실제저장소명) · [Demo ↗](실제데모주소)
```

현재 이미지는 실행 화면이 아닌 ‘준비 중’ 표지입니다. 이 표지를 교체하거나 제거하면 됩니다. 카드 블록을 복사하거나 삭제해서 총 3~5개를 유지하세요. 이미지 폭은 960px 정도, GIF는 짧고 가볍게 준비하면 읽기 편합니다.

## 블로그 상태와 최근 글

현재 자동 갱신 워크플로는 저장소 쓰기 권한에 대한 사용자 승인 대기로 비활성화되어 있습니다. 최초 실행에서 RSS를 정상적으로 확인했으며, 예제 글만 있어 README를 변경하지 않았습니다. 승인 후 Actions에서 워크플로를 활성화하면 아래 일정으로 갱신합니다.

2026-09-30 확인 시 블로그는 접속 가능하며 Astro 기본 화면과 예제 글이 남아 있습니다. 상단 링크에는 ‘블로그 준비 중’을 표시했고, 예제 글은 최근 글에서 제외합니다.

`.github/workflows/update-blog.yml`은 매일 한국 시간 오전 9시 17분경 RSS를 확인합니다. GitHub Actions 스케줄은 지연될 수 있습니다. 처음 실제 글을 올린 뒤 **Actions → Update blog posts → Run workflow**로 바로 갱신할 수도 있습니다.

- RSS 주소: `https://kanghyuckmoon.github.io/rss.xml`
- 표시 개수: 최신 3개 (발행일 기준, 미래 글 제외)
- 예제 제외: Astro 기본 글의 경로와 기본 제목 조합이 일치할 때만 제외합니다. 같은 경로의 글을 본인 글로 바꿔 제목을 변경하면 노출됩니다.
- RSS를 가져오지 못하거나 XML 형식이 잘못되면 기존 README를 유지하고 작업을 실패 처리합니다.
- 실제 글이 없다면 준비 중 문구를 표시합니다.
- 글이 올라오면 상단의 ‘블로그 준비 중’ 소개 문구는 직접 수정하세요.

추가 서비스나 개인 토큰은 필요하지 않습니다. 저장소 기본 `GITHUB_TOKEN`의 `contents: write` 권한을 사용합니다. 저장소 정책이 직접 커밋을 제한하면 Actions 로그에서 실패 원인을 확인하세요.

자동 갱신을 멈추려면 Actions에서 **Update blog posts → Disable workflow**를 선택하세요. 수동 갱신 시에는 `BLOG-POST-LIST` 주석 사이에 Markdown 링크를 적습니다.
